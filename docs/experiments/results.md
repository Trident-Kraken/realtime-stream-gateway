# Experiment results (schema v2, 2026-11-03)

Generated by `python3 tools/summarize_experiments.py docs/experiments`.

Historical schema-v1 results are superseded: they used inconsistent windows,
duplicated TCP frame boundaries, receiver-visible denominators, and seeds 0..4
when the CLI was passed hexadecimal text. They are not comparable to this run.

## Conditions and denominators

- Virtual clock; 30 fps; 12,000 media bytes/frame; 10 fragments/frame;
  10 ms base RTT with independent ±2 ms one-way jitter; 100 ms sender budget;
  60 ms receiver playout delay; all synthetic frames independently decodable.
- Exactly 100 warmup + 10,000 measured source frames per run; frame IDs
  `[100, 10100)` only. Bounded 2-second recovery tail, followed by RUDP shutdown.
- Five seeds 24301..24305 (`0x5EED..0x5EF1`), including fanout.
- Playout FDR = unique on-time frame/client pairs / (10,000 × clients).
  Missing sessions, wholly lost frames and pre-admission drops remain in the denominator.
- Session FDR = on-time cumulative-ACK closure / `session_offered`; this
  is a sender-side confirmation measurement, not decoded playback.
- Same fault distribution across arms; packet-dependent RNG consumption means
  the exact loss sequence differs across arms. TCP-model is an ordered byte-stream
  model with duplicate-ACK recovery and 200 ms RTO floor, no SACK or congestion control.
  It is not a measurement of Linux TCP, QUIC, SRT, or WebRTC.

## Deadline ablation

- bench-comparison: paired playout-FDR deltas by seed = +0.0007, -0.0018, -0.0002, -0.0004, -0.0001; mean -0.0004.
- bench-burst: paired playout-FDR deltas by seed = +0.0073, +0.0028, -0.0023, -0.0096, +0.0029; mean +0.0002.

The benefit varies by seed. These five runs do not establish a robust general
advantage of deadline mode over always-retransmit. The controlled interruption demo
separately demonstrates ABANDON progression and GOP recovery; it is not a throughput benchmark.

## Latency interpretation

RUDP playout P99 is 60 ms in these runs, measured against a timeline anchored
at the first valid packet arrival. This includes intentional jitter-buffer wait,
excludes the unknown initial capture-to-arrival offset, and conditions on delivery.
It is not glass-to-glass or synchronized capture-to-playback latency. UDP/TCP-model
latency samples are not collected (their JSON zero values mean unavailable).

## Reproduction

```bash
tools/run_benchmarks.sh docs/experiments
tools/run_fault_matrix.sh docs/experiments
tools/replay_trace.sh docs/experiments/fault-storm.json /tmp/storm-replay.json
python3 tools/summarize_experiments.py docs/experiments
```

Benchmark replay compares parsed JSON after excluding host CPU/RSS fields;
invalid JSON or unreadable inputs fail the check. Fault replay compares complete JSON.
Reproducibility is tested within this build/toolchain; cross-standard-library
bit identity is not guaranteed by the use of C++ random distributions.
