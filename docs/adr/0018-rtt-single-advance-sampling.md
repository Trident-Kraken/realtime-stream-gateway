# ADR-0018: RTT samples are taken only on single-packet cumulative advances

- **Status:** Accepted (Phase 2, found by fault injection)
- **Context:** The frozen v0.2 rule samples `now - first_send` of the oldest newly covered never-retransmitted packet on every cumulative ACK advance. When a hole exists, the next cumulative advance is delayed until the hole is repaired, so samples measure *recovery latency* (50–150 ms under 5% loss), not the ~10 ms path RTT. Inflated SRTT then (a) widens the sender's NACK suppression window (`now - last_send < SRTT`), slowing fast recovery until frames hit their deadline, and (b) inflates the RTO. Result: FDR 89% at 5% loss against the 95% release target (spec §8.2). Per spec §1, the acceptance criteria govern.
- **Decision:** A cumulative ACK advance yields an RTT sample only when it covers **exactly one** new sequence (`ack == last_valid_ack + 1`) and that packet was never retransmitted. Single-packet advances are in-order consumptions whose ACK was not delayed by hole repair, so they measure the true path RTT. Multi-packet advances (hole recoveries) and SACK-only ACKs produce no sample. RFC 6298 update and per-entry backoff are unchanged. Sample frequency remains high (one per in-order packet, ACK-per-DATA).
- **Alternatives rejected:** newest-of-batch sampling — still HOLB-contaminated; sender-side hole detection — not observable without wire changes (ADR-0002); widening the deadline — changes the frozen workload (spec §8.2).
- **Consequences:** SRTT/RTO track the path, recovery latency no longer feeds back into suppression and admission thresholds; fewer deadline abandonments under loss. Wire unchanged.
- **Test anchors:** RTT unit cases updated for the single-advance rule; fault-injection rows assert FDR targets (docs/experiments/).
